# 06 — Phase 5: File Data Migration

> **Depends on**: Phase 4 (DB already knows the users/storages so files map to the right accounts)
> **Blocks**: Phase 6 (repair/rescan operate on the files present on disk)
> **Goal**: Copy the actual user file data from the old server's data directory to the new server's, preserving ACLs, extended attributes, and ownership.

The database migration (Phase 4) created the users and storage records. Now we place the files on disk where those records point. `rsync -Aax` preserves the POSIX ACLs (`-A`), all filesystem xattrs (`-X` via `-a`), and recurses preserving everything (`-a`).

## Subtasks

### 5.1 Confirm old and new data directory paths
From Phase 0.2:
- Old data dir: `<old_datadirectory>` (e.g. `/var/www/nextcloud/data`)
- New data dir: `<new_datadirectory>`

Confirm both exist and the new data dir is on a volume with enough free space (Phase 0.5 old size vs. new free space).

### 5.2 Run rsync for each user folder
Two options for transport:

**Option A — server-to-server rsync over SSH (preferred if old server can reach new):**
```
rsync -Aax --info=progress2 --partial \
  root@38.242.141.240:<old_datadirectory>/ \
  <new_datadirectory>/
```

**Option B — pull to local PC, then push (if servers cannot talk directly):**
```
rsync -Aax --partial root@38.242.141.240:<old_datadirectory>/ ./nextcloud-data-staging/
rsync -Aax --partial ./nextcloud-data-staging/ root@164.68.104.123:<new_datadirectory>/
```

Per-user (safer, resumable) variant:
```
for u in $(ssh root@38.242.141.240 "ls <old_datadirectory>"); do
  rsync -Aax --partial \
    root@38.242.141.240:<old_datadirectory>/$u/ \
    root@164.68.104.123:<new_datadirectory>/$u/
done
```

### 5.3 Preserve ACLs / xattrs / ownership
- `-A` preserves ACLs.
- `-a` (archive) preserves ownership, group, permissions, times, symlinks.
- `-x` stays on one filesystem (do not cross mount points into e.g. `/proc`).
- Verify the web server user on the new server (Phase 0.2, e.g. `www-data`) matches what rsync delivers. If the old server used a different user, ownership must be fixed in 5.4.

### 5.4 Fix ownership/permissions on the new server
After rsync, ensure the new server's web user owns everything:
```
ssh root@164.68.104.123 "chown -R www-data:www-data <new_datadirectory>"
ssh root@164.68.104.123 "find <new_datadirectory> -type d -exec chmod 770 {} \;"
ssh root@164.68.104.123 "find <new_datadirectory> -type f -exec chmod 660 {} \;"
```
- Directory perms `770`, file perms `660` is the Nextcloud default for the data dir.
- Adjust the user (`www-data`) per the new server's actual web user from Phase 0.2.

### 5.5 Verify file counts and total sizes match
On both servers:
```
find <datadirectory> -type f | wc -l
du -sb <datadirectory>
```
Old and new counts/sizes should match (modulo any files excluded intentionally). For a stronger check, sample a few files and compare checksums:
```
ssh root@38.242.141.240 "sha256sum <old_datadirectory>/<user>/path/to/file"
ssh root@164.68.104.123 "sha256sum <new_datadirectory>/<user>/path/to/file"
```

### 5.6 Handle appdata and uploads directories
- `appdata_*` — generated app data (previews, avatars). These can be rsynced to save regeneration time, OR skipped and regenerated by `occ maintenance:repair` / preview generation. Decision:
  - **rsync them** if you want to preserve existing previews/avatars exactly.
  - **skip them** if you'd rather regenerate (cleaner, but slower first run).
- `uploads/` — chunks of in-progress uploads. Safe to skip (they belong to abandoned uploads from before maintenance mode). Skip unless a user had a critical upload in flight.
- `__groupfolders/` — group folders data; rsync if the groupfolders app is in use (Phase 3/4).

## Exit Criteria
- [ ] All user folders copied to the new data dir
- [ ] Ownership = web user on the new server
- [ ] Permissions: dirs 770, files 660
- [ ] File counts and total size match old vs. new
- [ ] Sample checksums match
- [ ] appdata / uploads / groupfolders handled per decision above

## Notes
- rsync can be re-run safely; it only transfers differences. If interrupted, just re-run the same command.
- Do NOT rsync the old server's `config/` directory — that would overwrite the new server's system config.
- The `oc_filecache` rows imported in Phase 4 reference files by storage+path; as long as the files land at the same relative path under the new data dir, the mapping holds. Phase 7's scan reconciles any drift.
